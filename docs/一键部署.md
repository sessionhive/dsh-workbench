# 一键部署

从 Git 克隆后，在 `app` 目录运行一个脚本，就能建好目录、装好引擎和插件并启动工作台，不需要逐条手工操作。

## 1. 运行

```powershell
git clone https://github.com/sessionhive/dsh-workbench.git app
cd app
node scripts/setup.mjs
```

Windows 也可以双击 `scripts\setup.cmd`。想先确认会做什么、不写任何文件：

```powershell
node scripts/setup.mjs --dry-run
```

要求：Node.js 20+、npm 可用、首次部署能联网。已安装 DSH 时可以跳过下载，文件、终端、网页和待办也能在没有引擎时使用。

## 2. 脚本做了什么

1. 创建 `<root>/engines`、`<root>/data/.dsh`、`<root>/workspace`、`<root>/_dev/tools`；
2. 安装并构建工作台；存在 `src/modules/local-modules/` 时自动用本机扩展构建，也可以用 `--public` / `--local` 强制选择；
3. 下载 `@deepseek-ai/dsh`（默认 `0.2.2-rc.3`）并暴露 `<engines>/apps/cli/lib/bin.js`；
4. 数据目录未初始化时，临时启动一次 `dsh web` 生成 `_meta/`；
5. 探测 DSH profile，安装 `@sessionhive/dsh-collab`（默认 `0.2.0`），备份并把 `workbench-core` 条目写进 `cordis.patch.yml`；
6. 再启动一次引擎，生成插件清单与 `_meta/registry.json`；
7. 启动工作台客户端，并等待引擎端口就绪。

脚本是幂等的：重复运行会复用已有目录、跳过已安装的插件，并在改动 `cordis.patch.yml` 前自动备份。它不会读取 `.credentials.yaml`，也不会结束不是它启动的进程。

## 3. 默认目录

以仓库位于 `<root>/app` 为例：

| 用途 | 默认位置 |
| --- | --- |
| 引擎安装目录 | `<root>/engines`（存在 `apps/cli/lib/bin.js`） |
| 引擎数据目录 | `<root>/data/.dsh`（存在 `_meta/registry.json`） |
| 工作区 | `<root>/workspace` |
| 工具目录 | `<root>/_dev/tools` |
| 引擎端口 | `3083` |

目录可以不改，直接在设置页「引擎」里逐项覆盖；也可以用 `DSH_ENGINE_DIR`、`DSH_HOME`、`DSH_PORT` 环境变量。

## 4. 参数

| 参数 | 说明 |
| --- | --- |
| `--root <dir>` | 仓库的上一级目录，默认是 `app/` 的父目录 |
| `--engine-dir <dir>` | 引擎安装目录，默认 `<root>/engines` |
| `--dsh-home <dir>` | 引擎数据目录，默认 `<root>/data/.dsh` |
| `--port <n>` | 工作台引擎端口，默认 `3083` |
| `--dsh-version <ver>` | `@deepseek-ai/dsh` 版本，默认 `0.2.2-rc.3` |
| `--plugin-version <ver>` | dsh-collab 版本，默认 `0.2.0` |
| `--skip-build` | 跳过依赖安装与构建（`dist/` 必须已存在） |
| `--skip-launch` | 安装完成后不启动工作台 |
| `--skip-port-check` | 跳过端口占用检查（仅建议配合 `--dry-run`） |
| `--public` / `--local` | 强制公开构建 / 本机扩展构建 |
| `--no-init` | 数据目录未初始化时直接报错，不临时启动引擎 |
| `--dry-run` | 只检查并打印将执行的操作，不写文件、不安装、不启动 |

完整列表以 `node scripts/setup.mjs --help` 为准。

## 5. 验收

脚本结束后依次确认：

1. 底栏右侧显示「DSH 引擎已连接」，左侧能看到引擎会话数量。
2. 「设置 → 引擎」里的引擎目录、数据目录、工作区路径都存在。
3. 「设置 → 体检」里环境、路径、引擎没有 fail；「核心插件」允许出现 warn，但不能 fail。
4. DSH 页面里「设置 → 会话协作」能打开，协作看板 `/plugins/workbench-core/board` 有内容。
5. 新建一个会话，在会话桌面添加文件或终端盒子，按 `Ctrl + S` 保存后重启客户端，布局仍在。

还需要在 DSH 里登录模型账号；脚本不读取、也不写入任何凭据。

## 6. 常见问题

**Electron 或 esbuild 安装后缺少二进制。**
npm 11 默认跳过依赖的安装脚本。仓库和引擎的 `package.json` 已经用 `allowScripts` 按包名放行；如果仍然失败，先确认 npm 版本，再重新执行 `npm install`，不要用全局安装替代。

**端口 3083 被占用。**
脚本会先识别占用者，只清理自己上次异常退出留下的 `dsh web`；外部 DSH 或其他服务只提示、不结束。关掉占用者，或用 `--port` 换端口。

**插件装了但面板还是空的。**
确认 `cordis.patch.yml` 在正确的 profile 里、`node_modules/@sessionhive/dsh-collab` 存在、YAML 没有语法错误，然后重启引擎。手动排查步骤见 [引擎与插件](引擎与插件.md)。

**找不到 `_meta/registry.json`。**
数据目录还没初始化。去掉 `--no-init` 重跑，让脚本临时启动一次引擎；或先手动运行 `dsh web` 初始化。

**引擎启动超时。**
在 `app` 目录前台运行 `npm start` 看日志，检查 `DSH_NODE` 是否指向可用的系统 Node，以及原生模块的 ABI。脚本不会结束未知进程。

**路径里有空格或中文。**
命令行参数用引号包住；YAML 里的 `dataRoot` 由脚本写入，不需要手改。

## 8. 安全边界

- 不读取、复制或提交 DSH 的 `.credentials.yaml`。
- 不结束不是脚本启动的 Electron、Node 或 `dsh web` 进程。
- 端口被外部占用时停止并提示，不强行清理。
- 修改 `cordis.patch.yml` 前备份；已有同名插件条目时只修 `dataRoot`，不重复插入。
- 不执行 `git push`，不提交本地状态、截图或引擎数据。
- 插件数据默认保留；需要回滚时先退出工作台，再用备份恢复 profile 配置。
